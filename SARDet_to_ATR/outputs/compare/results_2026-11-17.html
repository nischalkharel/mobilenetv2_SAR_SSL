Self-supervised learning on SARDet-100K: what transfers

MobileNetV2 from ImageNet weights, then 100 epochs of SSL on 94,034 unlabeled SARDet-100K scenes, then supervised fine-tuning with 1, 3 or 10 % of the labels. Two downstream tests: the same dataset (detection, mAP) and a different one (ATRNet-STAR vehicle chips, 40-class accuracy). Three splits per cell; every difference is paired on the same split and labeled set. RegionDINO adds object views cut around label-free regions; its control cuts the same windows at random places. Every ATRNet figure keeps two blocks apart: SSL on ATRNet-STAR chips (in-domain: the earlier A-series, P4, and the arm-I rows that run the RegionDINO engine on the same chips) and SSL on SARDet-100K scenes (cross-dataset, the XA rows). Compare a row with the rows of its own block; the gap between the blocks is the transfer question itself.

ATRNet-STAR, RegionDINO object-only vs plain DINO
+9.41 % labels
Object views turn a cross-dataset loss into a gain

27.2 / 49.0 / 73.7 % against plain DINO's 17.8 / 41.8 / 72.3: +9.4 / +7.1 / +1.4 points, positive on all nine cells, and +6.4 / +5.5 / +2.0 over no SSL. The random-window control gets only a third of that gain.

ATRNet-STAR, RegionDINO scene+object vs plain DINO
+3.93 % labels
Keeping the scene views costs most of the gain

20.2 / 45.7 / 73.4 % against plain DINO’s 17.8 / 41.8 / 72.3: +2.5 / +3.9 / +1.1 points, positive on all nine cells but a third of object-only. Its control sits at the plain-DINO level, and so do its response maps: with scene views in the loss the backbone does not settle on the vehicle.

−2.0object-only, 1 % labels
On target-centred chips the object views do not help

Plain DINO of the same engine 34.0 / 56.2 / 77.3 % (A1: 35.1 / 55.9 / 77.6). Scene+object 33.8 / 55.8 / 77.1, level with it. Object-only 32.0 / 54.5 / 75.7: −2.0 / −1.8 / −1.6, negative on all nine cells. The gain is a cross-dataset effect: it appears when the SSL images are large scenes and the test is a chip.

Where the numbers come from
ATRNet-STAR table: SARDet_to_ATR/compare.py → SARDet_to_ATR/outputs/compare/cross_dataset.csv. Model selection: epoch with highest validation accuracy; the official test set is scored once.
Detection tables: SARDet/compare/compare.py → SARDet/compare/outputs/20261117-223630/ (summary.md, runs.csv, per_source.csv). Model selection: best validation mAP on the 800-image selection set.
SSL and fine-tune runs: CRC A100 40 GB, repository commits b111bda, 45eb52e, 0c2d206, 40a4bab and 64b9420 (results), SSL runs at 7aea6de and earlier. Arm-I fine-tunes: CRC jobs 4762649 to 4762663 (SARDet_to_ATR/crc.sbatch, methods atr_*), run folders XI_*. SSL export rule: final epoch, no selection. Fine-tune seeds fixed at 0; splits differ in labeled set and SSL seed.
Response maps: SARDet_to_ATR/response_maps.py (CRC job xa_maps 4762232, 2026-11-19, with the scene+object and arm-I backbones) → SARDet_to_ATR/outputs/compare/response_maps.md, per-model and per-chip CSVs, split-1 figure. Same measure as the earlier A1-vs-P4 saliency study. Scene version: RegionSSL/scene_maps.py (CRC job scene_maps 4763033, 2026-11-19) → RegionSSL/outputs/scene_maps/ (scene_maps.md, per-model, per-image and per-source CSVs, split-1 figure).
