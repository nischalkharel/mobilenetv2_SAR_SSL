What has been run, and what it says

Every row of this study is one recipe: unlabeled pool for self-supervised learning (SSL) → labeled set for fine-tuning → task that is scored. MobileNetV2 from ImageNet weights everywhere, 100 SSL epochs, 1 / 3 / 10 % of the labels, three splits per cell, official test sets. Numbers on this page are read from the run folders; the sentences are the current reading and are updated by hand.

no SSL or SSL on ATRNet-STAR chips or SSL on SARDet-100K scenes → fine-tune on ATRNet-STAR labels or on SARDet-100K labels → classification accuracy or detection mAP
Row labels in one line. A0 = ImageNet weights, no SSL. A1 / A2 / A3 = DINO / LeJEPA / SparK with SSL on the ATRNet chips. P4 = CondDINO (uses metadata). XA = SSL on SARDet scenes, tested on ATRNet chips (cross-dataset). XI = the RegionDINO engine on the ATRNet chips (the in-domain check, also called arm I). control = same method minus the ingredient under test. Everything else: glossary.

Reading, 2026-11-20

In-domain (SSL and test both on ATRNet chips): any SSL helps a lot at 1 % labels (21 → 35 to 41 %). CondDINO is top but uses acquisition metadata, so it sits apart. Plain DINO and LeJEPA tie. SparK is weakest here.

Cross-dataset (SSL on SARDet scenes, test on ATRNet chips): plain DINO and LeJEPA transfer worse than no SSL. RegionDINO object-only turns that into the best cross-dataset row (+9.4 over plain DINO at 1 %), with SparK second. The random-window control gets a third of the gain, so the regions matter. Cross-dataset is still far below in-domain (27 vs 35 at 1 %).

RegionDINO on the ATRNet chips themselves (the XI rows, also called arm I): no gain. Scene+object is level with plain DINO, object-only is 2 points below. A chip is already the object; cutting regions out of it only removes context. So the object views pay off when the SSL images are scenes and the test is a chip, and that is the setting to build the paper on.

Detection (SSL and test on SARDet): RegionDINO object-only is the first method to move SARDet detection by more than a point: +1.6 / +1.4 / +1.2 mAP points at 1 / 3 / 10 %, positive on all nine cells, against SparK's +0.7. But its random-window control gets the same (+1.8 / +1.6 / +1.0). So for detection the gain comes from training DINO on small object-sized crops instead of whole scenes, not from where the crops are placed. Scene+object gives half of that and its control a third.

Chip classification on SARDet itself (S1): a null. No SSL already reaches 81 % mean per-class accuracy at 1 % labels (92 % overall) and every SSL row lands within split noise of it. The six coarse classes are too easy, and the splits differ by up to 7 points, more than any method difference. Study S2 (tiles) is parked; a harder version of this test (smaller budget, or train and test on different source datasets) would be the way to get signal from chips.

Next: a classification test where the SSL pool is large scenes and the labeled chips come from the same sensor (Sentinel-1 scenes + OpenSARShip chips, or chips cut from SARDet boxes), and later a non-SARDet scene pool (Umbra / Capella). Ideas and doubts go in the idea box.
